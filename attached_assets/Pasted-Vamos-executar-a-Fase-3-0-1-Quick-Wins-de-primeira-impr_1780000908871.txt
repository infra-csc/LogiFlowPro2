Vamos executar a Fase 3.0.1 — Quick Wins de primeira impressão e layout público.

Objetivo:
Corrigir problemas visuais P0 encontrados na auditoria da Fase 3 sem alterar regra de negócio, RBAC, endpoints, payloads ou banco.

Contexto:
A auditoria visual da Fase 3 identificou como problemas P0:
- Dashboard retorna 404.
- Login aparece dentro do layout com sidebar.
- Microcopy EN/PT misturado em telas de erro, como “404 Page Not Found” e “Back to Dashboard”.

Antes de criar o Design System base da Fase 3.1, quero corrigir esses pontos de primeira impressão.

Escopo permitido:

1. Corrigir rota /dashboard

Opções aceitáveis:
- Redirecionar /dashboard para /, se / já for a tela inicial real do app.
ou
- Criar uma página Dashboard simples usando dados já existentes, sem criar endpoint novo.

Preferência:
- Se já existir rota inicial funcional em /, fazer redirect /dashboard → /.
- Não criar endpoint novo.
- Não inventar cards ou métricas fictícias.

Regras:
- Não alterar autenticação.
- Não alterar ProtectedRoute se não for necessário.
- Não alterar back-end.
- Não alterar payloads.
- Não criar dashboard complexo nesta fase.

- /auth
- /forgot-password

Essas páginas não devem aparecer dentro do layout interno com sidebar.

Implementar ou ajustar:

- Sem navegação interna.
- Visual limpo, centralizado e profissional.
- Manter paleta atual do sistema.
- Manter formulários e lógica existentes.
- Não alterar payloads de login/reset.
- Não alterar chamadas de API.
- Não alterar regras de autenticação.
