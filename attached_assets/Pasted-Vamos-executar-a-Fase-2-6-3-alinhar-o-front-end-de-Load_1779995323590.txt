Vamos executar a Fase 2.6.3 — alinhar o front-end de Loading Orders às roles Almoxarifado e Supervisor.

Objetivo:
Atualizar a UX de Loading Orders para refletir as permissões aplicadas no back-end na Fase 2.6.2, sem alterar regras de back-end, endpoints, payloads, banco ou roles.

Contexto:
Na Fase 2.6.2, o back-end passou a aplicar:

* Almoxarifado em:

  * POST /api/loading-orders/:id/items
  * POST /api/loading-orders/:id/mark-ready

* Supervisor em:

  * POST /api/loading-orders/:id/approve
  * POST /api/loading-orders/:id/disapprove

Permissões atuais efetivas:

* Admin: tudo.
* Logística: criar/editar/otimizar loading-orders, adicionar itens, marcar pronta, vincular/desvincular viagens.
* Almoxarifado: adicionar itens e marcar pronta.
* Supervisor: aprovar e desaprovar.
* Usuário comum: apenas leitura.

Agora o front-end precisa esconder/desabilitar ações conforme essa matriz para evitar UX ruim de clique seguido de 403.

Regras obrigatórias:

* Não alterar back-end.
* Não alterar banco.
* Não criar migration.
* Não alterar seed.
* Não alterar endpoints.
* Não alterar payloads.
* Não alterar middlewares.
* Não alterar ProtectedRoute.
* Não alterar sidebar, pois leitura de Loading Orders continua liberada para qualquer usuário logado.
* Não consumir permissions/role_permissions.
* Não criar roles novas.
* Não refatorar layout inteiro.
* Não fazer redesign.
* Não criar any/as any.
* Não alterar módulos fora de Loading Orders.

Escopo permitido:

1. Usar helper de RBAC já existente no front

Reutilizar:

* client/src/lib/authz.ts
* ROLES de shared/roles.ts
* userHasRole / userHasAnyRole / userIsAdmin, ou funções equivalentes já criadas

Se faltar helper específico, criar apenas helpers pequenos, por exemplo:

* userIsLogistica(user)
* userIsAlmoxarifado(user)
* userIsSupervisor(user)
* userCanManageLoadingOrders(user)
* userCanHandleLoadingOrderItems(user)
* userCanMarkLoadingOrderReady(user)
* userCanApproveLoadingOrder(user)
* userCanOptimizeLoadingOrder(user)

Regras esperadas:

* canManageLoadingOrders = Admin ou Logística
* canHandleLoadingOrderItems = Admin ou Logística ou Almoxarifado
* canMarkLoadingOrderReady = Admin ou Logística ou Almoxarifado
* canApproveLoadingOrder = Admin ou Supervisor
* canOptimizeLoadingOrder = Admin ou Logística
* canLinkTrips = Admin ou Logística
