Resultado da Auditoria Visual
1. Diagnóstico Geral do Design
O sistema está visualmente coerente, mas ainda funcional demais. A paleta dark navy com azul ciano e rosa funciona bem. A sidebar está bem organizada. Os formulários são robustos. Mas falta polimento: componentes replicados manualmente, telas densas demais, e algumas decisões de layout que prejudicam a primeira impressão.

Pontos fortes:

Paleta coerente e sem poluição cromática
Sidebar bem estruturada com grupos colapsáveis
Formulários consistentes (React Hook Form + Zod)
RBAC visual funcional — botões ocultos corretamente
Badges de status centralizados (em parte)
Pontos fracos:

Componentes de loading, empty state e header de página replicados manualmente em ~15 telas
Algumas telas densas demais (movement-details com 1.565 linhas, movement-dialog com 543)
Login aparece dentro do layout com sidebar visível
Dashboard retorna 404
Devoluções não têm botão de criação no front

6. Proposta de Design System Leve
Sem troca de identidade visual. Manter a paleta atual, a fonte Inter, e o shadcn/ui.

Tokens propostos:

Padding de página: p-6 (manter)
Cards com cor sutil de fundo por status (não borda lateral — evita problema com rounded)
Badges: verde = positivo, laranja = pendente/alerta, vermelho = erro, azul = ativo/novo, cinza = inativo
Padrões:

PageHeader: h1 + p descritivo + ações (slot) — em todas as páginas
DataCard: card com ícone, título, badge de status, metadados — para listagens
FilterBar: colapsável com Collapsible — para telas com filtros
EmptyState: ícone + título + descrição + CTA opcional — para todos os estados vazios

8. Primeira Fase Recomendada
Fase 3.1 — Design System Base + Fase 3.9 — Login/Auth Flow

Por que começar por essas duas:

São componentes puros (sem lógica de negócio)
Risco baixo
Impacto visual alto
Uma vez criados, as fases 3.2–3.8 ficam mais rápidas
Corrigem a primeira impressão (login + dashboard)
Ordem sugerida:

3.1 + 3.9 em paralelo (base + login)
3.2 + 3.3 em paralelo (movimentações + loading orders)
3.4 + 3.6 em paralelo (requisições + devoluções)
3.5 (catálogo)
3.7 (admin)
3.8 (dashboard — por último, pois pode precisar de endpoint novo)
